**Sample image extraction:**
Write a one-time script (run it, don't commit it) that extracts 5 representative document images from the RVL-CDIP dataset cache or HuggingFace:

1. Use the cached features directory (.hf-cache-100k or .hf_cache_full) to find representative images, OR use `datasets` library to load a few samples from the test split
2. Select one image from each of these 5 classes: invoice, letter, form, email, resume
3. Save as JPEG files in app/src/static/samples/:
   - sample_invoice.jpg
   - sample_letter.jpg
   - sample_form.jpg
   - sample_email.jpg
   - sample_resume.jpg
4. Resize to reasonable display size (max 800px on longest side) to keep file size small

If the dataset cache is not available locally, create 5 synthetic placeholder images using PIL:
- 400x500 grayscale images with the class name written as text
- These are functional placeholders that let the pipeline run end-to-end
- Replace with real samples when dataset is available

**Update base.html sample thumbnails:**
- Update the sample thumbnail grid to show actual images from /static/samples/
- Each thumbnail: `<img src="/static/samples/sample_invoice.jpg" alt="invoice sample" class="w-full h-24 object-cover rounded-lg">`
- Each sample card submits via HTMX: `hx-post="/classify" hx-target="#results" hx-swap="innerHTML"` with `hx-vals='{"sample_name": "sample_invoice.jpg"}'`

**Route tests (app/tests/test_routes.py):**
Write tests using FastAPI TestClient:

1. test_home_page: GET / returns 200, contains "Document Classification" in body
2. test_classify_with_upload: POST /classify with a small test image file (generate a 100x100 PIL Image, save to BytesIO as JPEG), verify returns 200
3. test_classify_with_sample: POST /classify with sample_name="sample_invoice.jpg" (if sample exists), verify returns 200
4. test_classify_returns_html: POST /classify with HX-Request header, verify response contains expected HTML elements (model names, confidence percentages)

Note: These tests will be slow because they load models. Mark them with pytest.mark.slow if desired. For CI, the tests validate the route logic; for local dev they validate end-to-end.

Use conftest.py fixture for TestClient.
