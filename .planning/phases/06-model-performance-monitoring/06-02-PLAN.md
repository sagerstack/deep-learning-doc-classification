<task type="auto">
  <name>Task 1: Build the Evidently batch monitoring job</name>
  <files>pyproject.toml, .env.example, app/src/monitoring/store.py, scripts/monitoring/run_evidently.py</files>
  <action>
Add the Evidently-driven monitoring job as a script outside the request path.

1. Add `evidently` plus any missing dataframe dependency required by the chosen API to `pyproject.toml`.

2. Extend `.env.example` with Evidently settings:
   - `EVIDENTLY_API_URL` or workspace URL
   - `EVIDENTLY_API_KEY`
   - `EVIDENTLY_PROJECT_ID`
   - `EVIDENTLY_DASHBOARD_URL`
   - `EVIDENTLY_OFFLINE_OUTPUT_DIR` for local HTML/JSON output when cloud publishing is unavailable

3. In `app/src/monitoring/store.py`, add a helper that returns recent events as a pandas DataFrame for a time window.

4. Create `scripts/monitoring/run_evidently.py`:
   - load a reference dataset from `monitoring/reference/`
   - query current-window events from SQLite
   - group rows by `model_id`
   - for each model:
     - build an Evidently Dataset/DataDefinition with explicit prediction label column, probability columns, timestamp, and optional target column
     - create an unlabeled monitoring report that includes:
       - predicted class distribution
       - confidence distribution / drift
       - latency distribution / drift
       - input metadata drift (image dimensions, sample_type)
       - OCR/text-density availability rates
     - if `target` is present for the window, add a labeled quality report with accuracy, precision/recall/F1, and confusion trends
     - publish the run to the shared Evidently project with tags/metadata:
       - `env`
       - `model_id`
       - `model_version`
       - `batch_window`
       - `report_type` (`unlabeled` or `labeled`)
   - if Evidently cloud creds are absent, write local HTML/JSON artifacts to `EVIDENTLY_OFFLINE_OUTPUT_DIR` instead of failing

Use one report per model per window. Do not combine all models into a single report as the default production workflow.
  </action>
  <verify>
Run a local dry run that:
- seeds the monitoring DB with a few rows for at least two model_ids
- runs `scripts/monitoring/run_evidently.py --window-hours 24 --offline`
- writes separate output artifacts per model under the offline output directory
  </verify>
  <done>The repo can generate Evidently monitoring outputs per model from logged inference events, even without cloud credentials.</done>
