<task type="auto">
  <name>Task 1: Add monitoring configuration, schema, and SQLite event store</name>
  <files>pyproject.toml, .env.example, app/src/config.py, app/src/monitoring/schema.py, app/src/monitoring/store.py, app/src/main.py</files>
  <action>
Create an app-local monitoring module that persists one row per model prediction to SQLite.

1. In `.env.example` and `app/src/config.py`, add:
   - `EVIDENTLY_DASHBOARD_URL`
   - `MONITORING_DB_PATH` (default project-local SQLite file, e.g. `monitoring/data/inference_events.sqlite3`)
   - `APP_ENV` or similar env tag for dashboard/report metadata

2. Create `app/src/monitoring/schema.py` with:
   - a lightweight `InferenceEvent` dataclass or TypedDict
   - explicit probability column naming helper for all 16 classes
   - helper to flatten a model result plus shared request context into a single event row

3. Create `app/src/monitoring/store.py` with:
   - SQLite initialization function that creates the table if missing
   - `log_inference_events(events: list[InferenceEvent]) -> None`
   - query helpers for fetching events by time window and optionally by model_id
   - schema columns:
     - request_id, timestamp
     - sample_type, sample_name
     - image_width, image_height, image_mode
     - model_id, model_display_name, model_version
     - predicted_label, predicted_index, confidence
     - per-class probability columns
     - total_time_ms, feature_time_ms, graph_time_ms, model_time_ms
     - ocr_available, text_density_available
     - error_type nullable

4. Wire startup in `app/src/main.py` so the monitoring DB/table is created during app boot.

Use only stdlib `sqlite3` + project dependencies. Do not add a separate ORM.
  </action>
  <verify>
Run a short Python verification that:
- creates the DB in a temporary directory
- initializes the schema
- inserts two fake events for two different models
- queries them back and prints count=2
  </verify>
  <done>Monitoring storage exists, initializes on app startup, and supports inserting/querying per-model inference rows.</done>
</task>

Integrate monitoring into the serving flow and add the dashboard route.

1. In `app/src/routes/classify.py`:
   - generate a `request_id` for each classify action

   - after inference completes, build one monitoring event per `pipeline.results` row and persist them through `log_inference_events`
   - include availability flags such as whether `boc_features` or `text_density` were present
   - on failure paths, optionally persist an error event row with `error_type`

2. Add `app/src/routes/monitoring.py`:
   - `GET /model-performance`
   - if `EVIDENTLY_DASHBOARD_URL` is configured, return a redirect response to it
   - if unset, return a small HTML response that clearly states the dashboard URL is not configured yet

3. Register the monitoring route in `app/src/main.py`.

4. Update `app/src/templates/base.html` sidebar/nav to include:
   - label: `Model Performance`
   - href: `/model-performance`
   - open in same tab unless product requirements later change

5. Add tests:
   - route test for `/model-performance` redirect when env var exists
   - route test for fallback message when env var is missing
   - monitoring store integration test proving one classify request writes multiple rows, one per model result

Do not call Evidently from the route. This plan only establishes the event capture path and dashboard entrypoint.
