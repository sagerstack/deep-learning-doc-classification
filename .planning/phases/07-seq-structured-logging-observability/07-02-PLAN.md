<objective>
Build the structured logging backbone: a single `configure_logging()` entry point and a FastAPI middleware that generates a per-request UUID, binds request metadata into structlog contextvars, and ensures every log call made during the request automatically carries `request_id`, `method`, and `path`. Wire both into `app/src/main.py` so the plumbing is live for every incoming request.

Purpose: Plans 03 and 04 need a working structlog pipeline and a guaranteed `request_id` before they can emit meaningful events. Without this plan, calls to `structlog.get_logger().info(...)` would either produce unstructured output or lose correlation across the request lifecycle. This plan is the single point where the processor chain, Seq handler, and context propagation are decided — nothing else in the phase should touch logging setup.

Output:
- `app/src/logging_config.py` with `configure_logging()` implementing the processor-chain + stdlib-bridge + seqlog pattern from RESEARCH.md
- `app/src/middleware/logging.py` with `LoggingMiddleware` generating and binding `request_id`
- `app/src/middleware/__init__.py` (package init)
- `app/src/main.py` wired to call `configure_logging()` in the `lifespan` and register the middleware on the FastAPI app
</objective>

2. Calls `structlog.configure(...)` with:
   - `processors = shared_processors + [ProcessorFormatter.wrap_for_formatter]`
   - `logger_factory = structlog.stdlib.LoggerFactory()`
   - `wrapper_class = structlog.stdlib.BoundLogger`
   - `cache_logger_on_first_use = True`

4. Clears handlers on the root logger and attaches a `StreamHandler(sys.stdout)` using the formatter from step 3. Sets root level from `LOG_LEVEL` (reuse the existing `app.src.config.LOG_LEVEL`).

If the exact constructor signature differs in the installed seqlog version, use the supported entry point that attaches a handler WITHOUT clearing existing handlers. Do NOT call `seqlog.log_to_seq()` — Open Question 1 in RESEARCH.md documents it may clear the root logger's handlers and conflict with the stdout handler.
6. Silences Uvicorn's default handlers so the stream becomes consistent (Pitfall 4 in RESEARCH.md):

```python
for name in ("uvicorn", "uvicorn.access", "uvicorn.error"):
    logging.getLogger(name).handlers.clear()
    logging.getLogger(name).propagate = True
```

Do not emit events from this module. Do not expose any other public functions. Keep the module single-purpose.

  <name>Task 2: Create middleware package with LoggingMiddleware</name>
  <files>app/src/middleware/__init__.py, app/src/middleware/logging.py</files>
  <action>
Create `app/src/middleware/__init__.py` as an empty package marker (single newline).

Create `app/src/middleware/logging.py` implementing `LoggingMiddleware(BaseHTTPMiddleware)` exactly as described by Pattern 2 in RESEARCH.md:

```python
import uuid

import structlog
from starlette.middleware.base import BaseHTTPMiddleware
from starlette.requests import Request


class LoggingMiddleware(BaseHTTPMiddleware):
    async def dispatch(self, request: Request, call_next):
        structlog.contextvars.clear_contextvars()
        structlog.contextvars.bind_contextvars(
            request_id=str(uuid.uuid4()),
            method=request.method,
            path=request.url.path,
        )
        response = await call_next(request)
        return response
```

`clear_contextvars()` MUST be the first line of `dispatch()`. Without it, request_id from a prior request can leak into the next request on the same asyncio coroutine (Pitfall in RESEARCH.md). Bind `request_id`, `method`, and `path` only — user-action fields (`action_type`, `sample_name`, etc.) are bound later in Plan 03 at the route handler, where they are actually known.

Do not re-bind `environment` here — it is bound once in `configure_logging()` and survives across `clear_contextvars()` calls? Actually, `clear_contextvars()` clears ALL contextvars including `environment`. Re-bind `environment` in the middleware after clearing:

```python
from app.src.config import ENVIRONMENT
# ...
structlog.contextvars.bind_contextvars(
    environment=ENVIRONMENT,
    request_id=str(uuid.uuid4()),
    method=request.method,
    path=request.url.path,
)
```

This guarantees every request starts with a clean context but still carries the environment field (per CONTEXT.md schema).

Do not wrap `call_next` in try/except in this middleware — route-level failure events are emitted by Plan 03 inside the route handler where the full request body context is available. Exceptions propagate to Starlette's default exception handler unchanged.
  </action>

Static check: `grep -n \"clear_contextvars\\|bind_contextvars\" app/src/middleware/logging.py` must show both calls in the correct order (clear before bind).
  </verify>
  <done>
`LoggingMiddleware` is importable, subclasses `BaseHTTPMiddleware`, clears contextvars first, and binds `environment`, `request_id`, `method`, `path` before delegating to the downstream handler.
