<objective>
Provision the Seq log sink as a Docker Compose service alongside the existing FastAPI app, declare the Python logging dependencies (structlog + seqlog), and wire all required environment variables through config.py so the rest of the phase has a stable infrastructure baseline.

This plan establishes those prerequisites so the logging-core and emission plans can run in parallel without infra concerns.

<task type="auto">
  <name>Task 1: Add Seq service to Docker Compose with named volume</name>
  <files>docker-compose.yml</files>
  <action>
Add a new `seq` service to `services:` in `docker-compose.yml` alongside the existing `app` and `monitoring` services. Use the pattern from the research document verbatim:

```yaml
  seq:
    image: datalust/seq:latest
    environment:
      ACCEPT_EULA: "Y"
    ports:
      - "5341:80"
    volumes:
      - seq-data:/data
    restart: unless-stopped
```

Append a top-level `volumes:` block declaring the named volume:

```yaml
volumes:
  seq-data:
```

If a `volumes:` block already exists, add `seq-data:` to it (do NOT duplicate the key). Do not modify the existing `app` or `monitoring` service definitions in this task — that stays surgical. Place the `seq` service after `monitoring` to keep the file grouped by function.

Why `ACCEPT_EULA: "Y"` is mandatory: the `datalust/seq` container exits immediately without it (see Pitfall 5 in RESEARCH.md).

Why host port 5341 → container port 80: the container listens on port 80 internally for both UI and ingestion; host port 5341 is the Seq convention. Do not change this — Pitfall 1 in RESEARCH.md documents that misreading this mapping causes "connection refused" loops.
  </action>
  <verify>
Run `docker compose config` from the project root — command must succeed and the rendered output must contain `seq:` with `image: datalust/seq:latest`, `ACCEPT_EULA: "Y"`, the `5341:80` port mapping, and the `seq-data` volume binding. Run `docker compose up -d seq` — service must start and `docker compose ps seq` must report `running` (or `healthy`). `curl -sI http://localhost:5341` from the host must return an HTTP response (200 or 302 from Seq's UI is acceptable; connection-refused fails the task).
  </verify>
  <done>
Seq is a first-class service in `docker-compose.yml` with a named volume for persistence, uses the official image, has the EULA acceptance set, and is reachable from the host browser at http://localhost:5341.
  </done>
</task>

<task type="auto">
  <name>Task 2: Add Seq and environment config to config.py and .env files</name>
  <files>app/src/config.py, .env.example, .env.local</files>
  <action>
**In `app/src/config.py`**, after the existing `EVIDENTLY_DASHBOARD_URL` declaration (currently around line 40), add four new env-var reads following the same pattern used by the other config values. No hardcoded defaults other than what is documented here:

```python
# Seq structured logging
SEQ_SERVER_URL = os.environ.get("SEQ_SERVER_URL", "")    # empty disables Seq ingestion (non-fatal)
SEQ_API_KEY = os.environ.get("SEQ_API_KEY", "")          # blank = no auth (local dev)
SEQ_UI_URL = os.environ.get("SEQ_UI_URL", "http://localhost:5341")
ENVIRONMENT = os.environ.get("ENVIRONMENT", "local")
```

Rationale:
- `SEQ_SERVER_URL` default is empty so the app degrades gracefully if Seq is not running (same non-fatal pattern as monitoring). Plan 02 wraps handler setup in try/except when this is empty.
- `SEQ_UI_URL` default is `http://localhost:5341` because that is the host-facing nav target, not the intra-container one.
- `ENVIRONMENT` default is `local` per RESEARCH.md; it is emitted on every log event for later filtering.
- Do NOT add hardcoded URLs anywhere else — follow the existing project rule.

**In `.env.example`**, append a new section (after the existing Evidently block) documenting all four values with comments mirroring the style already used in the file:

```bash

# Seq structured logging
# SEQ_SERVER_URL: Seq ingestion URL. Leave blank to disable Seq ingestion (app still logs to stdout).
#   From inside Docker compose network: http://seq:80
#   From host Python (not Docker): http://localhost:5341
SEQ_SERVER_URL=

# SEQ_API_KEY: API key for authenticated ingestion. Blank for local dev (Seq container defaults to no auth).
SEQ_API_KEY=

# SEQ_UI_URL: Host-facing Seq UI URL. Used by the Observability nav link.
SEQ_UI_URL=http://localhost:5341

# ENVIRONMENT: local | prod. Emitted as a structured field on every log event.
ENVIRONMENT=local
```

**In `.env.local`**, append:

```bash
SEQ_SERVER_URL=http://seq:80
SEQ_API_KEY=
SEQ_UI_URL=http://localhost:5341
ENVIRONMENT=local
```

The `http://seq:80` value is correct for the app container's view of the Seq service via Docker internal DNS (Pitfall 1 in RESEARCH.md). Do not use `localhost` or `127.0.0.1` inside the container.
  </action>

  </verify>
