import structlog

log = structlog.get_logger()

(Place this alongside the existing `logger = logging.getLogger(__name__)` line. Do NOT delete the existing stdlib logger — monitoring failure warnings continue to use it so the "non-fatal" pattern stays visibly distinct from structured events.)

Add a helper to infer `sample_set` from the existing `sample` path parameter:

```python
def _infer_sample_set(sample_name: str | None) -> str:
    if not sample_name:
        return "upload"
    # sample is of the form "<category_key>/<filename>", e.g. "in-dist/invoice.jpg"
    category = sample_name.split("/", 1)[0] if "/" in sample_name else ""
    if category == "in-dist":
        return "in_dist"
    if category == "oo-dist":
        return "oo_dist"
    if category == "oo-dom":
        return "oo_dom"
    return "upload"
```

Rationale: `SAMPLE_CATEGORIES` in the same file already defines the canonical category keys (`in-dist`, `oo-dist`, `oo-dom`). Map those to snake_case slugs as required by CONTEXT.md (`in_dist`, `oo_dist`). `upload` is the correct fallback for file uploads (Task 2 wires this to the file path).

Now edit the `classify` handler (starts at `@router.post("/classify")`). At the TOP of the function — BEFORE the existing `if sample:` branch and BEFORE any image loading — do the following in order:

1. Determine action fields from the request params. Both branches set `action_type`, `sample_name`, and `sample_set`:

```python
if sample:
    action_type = "sample_click"
    sample_label = sample
    sample_set = _infer_sample_set(sample)
elif file and file.filename:
    action_type = "file_upload"
    sample_label = file.filename
    sample_set = "upload"
else:
    action_type = "unknown"
    sample_label = None
    sample_set = None
```

2. Image dimensions are NOT known yet (image is loaded below). Defer binding `image_width` / `image_height` until after the image is loaded, but bind the action fields now so they are on `request.received`:

```python
structlog.contextvars.bind_contextvars(
    action_type=action_type,
    sample_name=sample_label,
    sample_set=sample_set,
)
```

3. Emit `request.received` using currently-known fields:

```python
log.info(
    "request.received",
    event_type="request.received",
    action_type=action_type,
    sample_name=sample_label,
    sample_set=sample_set,
)
```

4. Keep the existing validation logic (404/400 short-circuits for missing sample / missing file). If either error path is taken, emit `request.failed` before returning:

```python
log.error(
    "request.failed",
    event_type="request.failed",
    error="No image provided. Upload a file or select a sample.",
    reason="missing_image",
)
```

(Adjust the reason string to match the actual validation branch — `"sample_not_found"` for the 404 path, `"missing_image"` for the 400 path.)

5. After successfully loading the image (right after `image = _load_image_from_upload(...)` or `image = _load_image_from_sample(...)`), bind the dimensions so they show up on every downstream event:

```python
structlog.contextvars.bind_contextvars(
    image_width=image.width,
    image_height=image.height,
)
```

6. Wrap the `_build_result_context(request, image, ...)` call in try/except. On success, emit `request.completed` using fields from the pipeline result that are already in the returned context. Use the context's `total_time_ms`, `model_details` (for `model_count`), and first entry of `results` (pipeline sorts by confidence desc already):

```python
try:
    context = _build_result_context(request, image, sample_type=..., sample_name=...)
except Exception as exc:
    log.error(
        "request.failed",
        event_type="request.failed",
        error=str(exc),
        exc_info=True,
    )
    raise

best = context.get("results", [None])[0] if context.get("results") else None
log.info(
    "request.completed",
    event_type="request.completed",
    total_latency_ms=context.get("total_time_ms", 0.0),
    model_count=len(context.get("results", [])),
    best_model_id=(best.model_name if best else None),
    best_predicted_class=(best.predicted_class if best else None),
    best_confidence=(best.confidence if best else None),
)
```

Preserve the existing `sample_type`/`sample_name` kwargs on the `_build_result_context` calls (the monitoring store uses them). Do NOT remove the existing monitoring log path — structured logging is ADDITIVE, the SQLite monitoring store from Phase 6 must keep working unchanged.

Field schema (must match CONTEXT.md exactly):
- `event_type` is always the dotted string `request.received` / `request.completed` / `request.failed`
- `model_id` / `best_model_id` is the slug (`cnn_baseline`, `fusion_graphsage`, `inductive_gcn`, `multimodal_gat`) — these are already the `InferenceResult.model_name` values returned by the pipeline
- `total_latency_ms` is a float, not a string

Do NOT add logs for sub-branches like "HTMX vs non-HTMX response" — one request produces exactly one `request.received` and exactly one `request.completed` OR one `request.failed`.
