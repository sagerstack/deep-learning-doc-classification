<objective>
Emit request-level structured events and user-action context from `app/src/routes/classify.py`, unify the monitoring-row `request_id` with the middleware `request_id`, and repoint the Observability nav item at the Seq UI. This is the first half of the "event emission" wave — Plan 04 handles the inference-layer events in parallel.

Purpose:
- Phase 7 Success Criterion 2 ("request received, request complete") and Criterion 3 ("user action log event with action type and metadata") both depend on events fired from the route. User-action fields must be bound via contextvars BEFORE inference runs, so the per-model events emitted by Plan 04 automatically inherit them without Plan 04 needing to know how a request arrived.
- Phase 7 Success Criterion 5 ("end-to-end trace correlation: one request_id propagates across middleware logs, route events, inference events, and the monitoring SQLite row") requires that `_build_result_context` use the SAME `request_id` the middleware bound. Today the function generates its own `uuid.uuid4()` internally, which splits the trace. This plan wires the middleware `request_id` in via an explicit parameter.
- Phase 7 Success Criterion 6 ("Observability nav item in the title bar links to the Seq UI") is pure configuration on the existing `NAV_ITEMS` tuple.

Output:
- Module-level `structlog.get_logger()` added to `classify.py`
- `_build_result_context()` gains a `request_id: str` kwarg and uses it for the monitoring row instead of generating its own UUID
- `classify` handler retrieves the middleware `request_id` from contextvars and passes it to `_build_result_context()`
- `bind_contextvars` call at the top of the `classify` handler with `action_type`, `sample_name`, `sample_set`
- `bind_contextvars` call after image load with `image_width`, `image_height`
- `request.received`, `request.completed`, `request.failed` events emitted at the correct points
- `NAV_ITEMS` Observability entry points at `SEQ_UI_URL` with `target="_blank"`

`request_id` is a required keyword-only argument (no default) — the caller MUST supply it. This makes it impossible for the monitoring row and log events to drift apart silently.

**Step B — Helper for sample_set inference.**

Add a helper to infer `sample_set` from the existing `sample` path parameter:

```python
def _infer_sample_set(sample_name: str | None) -> str:
    if not sample_name:
        return "upload"
    # sample is of the form "<category_key>/<filename>", e.g. "in-dist/invoice.jpg"
    category = sample_name.split("/", 1)[0] if "/" in sample_name else ""
    if category == "in-dist":
        return "in_dist"
    if category == "oo-dist":
        return "oo_dist"
    if category == "oo-dom":
        return "oo_dom"
    return "upload"
```

Rationale: `SAMPLE_CATEGORIES` in the same file already defines the canonical category keys (`in-dist`, `oo-dist`, `oo-dom`). Map those to snake_case slugs as required by CONTEXT.md (`in_dist`, `oo_dist`). `upload` is the correct fallback for file uploads.
