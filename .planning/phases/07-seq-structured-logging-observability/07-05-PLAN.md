<task type="checkpoint:human-verify" gate="blocking">
  <what-built>
Phase 7 delivers end-to-end observability: structlog + seqlog pipeline behind a request-scoped middleware, Seq Docker service for log aggregation, and structured events at every meaningful inference point (request.received, graph.built, model.inference, model.inference.failed, request.completed, request.failed). The Observability nav item in the top bar now opens the Seq UI.
  </what-built>
  <how-to-verify>
Perform each of the following and confirm before approving. If any step fails, describe exactly what you saw.

**Verification 1 — Observability nav link (Success Criterion 6)**
1. Open http://localhost:${APP_PORT:-9000}/ in a browser.
2. Click the "Observability" item in the top nav.
3. EXPECTED: A new tab opens to http://localhost:5341 showing the Seq UI events view.
4. FAIL: Nav opens in the same tab, or opens a `/observability` 404, or does not open Seq.

**Verification 2 — Sample-click flow produces a correlated event trail (Success Criteria 2, 3, 5)**
1. In the app UI, click one of the "In-Dist" sample thumbnails (e.g. "Invoice").
2. Wait for the results to render.
3. Switch to the Seq UI tab.
4. In Seq, filter: `event_type like 'request.%' or event_type like 'model.%' or event_type = 'graph.built'`.
5. Click the most recent `request.received` event and copy the `request_id` value.
6. Clear the event_type filter and apply: `request_id = '<paste id>'`.
7. EXPECTED: Seq shows exactly these events for this request_id (order is chronological):
   - 1 × `request.received` with `action_type = "sample_click"`, `sample_name = "in-dist/invoice.jpg"`, `sample_set = "in_dist"`
   - 1 × `graph.built` with numeric `graph_latency_ms`, `feature_extraction_ms`, `num_nodes = 49`, `knn_edges`
   - N × `model.inference` (one per model that ran; at minimum `cnn_baseline`), each with `model_id` as a top-level field (NOT in the message string), numeric `confidence`, array `top3_classes` of length 3
   - 1 × `request.completed` with numeric `total_latency_ms`, `model_count = N`, `best_model_id` as a slug, `best_predicted_class` as a human label
8. EXPECTED: `image_width` and `image_height` appear on at least `request.completed`.
9. FAIL: Any event missing; `model_id` embedded in message text instead of a sibling field; request_id differs across events; `sample_set` is `null` or wrong.

**Verification 3 — File upload flow (Success Criterion 3)**
1. In the app UI, use the upload input to submit any local image.
2. In Seq, find the new `request.received` event.
3. EXPECTED: `action_type = "file_upload"`, `sample_name = "<the uploaded filename>"`, `sample_set = "upload"`.
4. FAIL: `action_type` is `"unknown"` or `"sample_click"`; `sample_set` is anything other than `"upload"`.

**Verification 4 — Failure path (Success Criterion 7, descriptive logs for troubleshooting)**
1. From a terminal, run: `curl -s -X POST "http://localhost:${APP_PORT:-9000}/classify" -F "sample=in-dist/does-not-exist.jpg"`.
2. In Seq, filter `event_type = "request.failed"`.
3. EXPECTED: One event with `error` message mentioning the missing sample, the `request_id` unique to this failed request, `action_type = "sample_click"`, `sample_name = "in-dist/does-not-exist.jpg"`.
4. EXPECTED: The app is still serving requests — retry the sample-click flow from Verification 2 and confirm a fresh success trail.
5. FAIL: App crashed; no `request.failed` event; failure event is unstructured text.

**Verification 5 — Per-model filtering (Success Criterion 4)**
1. In Seq, filter: `event_type = 'model.inference' and model_id = 'cnn_baseline'`.
2. EXPECTED: Shows only CNN baseline events across all requests, each with `predicted_class`, `confidence`, and `top3_classes`.
3. Change the filter to `model_id = 'fusion_graphsage'` (or any other loaded GNN slug).
4. EXPECTED: Shows only that model's events.
5. FAIL: Filtering by `model_id` does not work (field is not indexed by Seq, meaning it was emitted as a message-string fragment instead of a structured field).
